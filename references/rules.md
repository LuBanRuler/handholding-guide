# 版式与文案规则

这些不是审美偏好，是踩过的坑。改图前先过一遍。

## 1. 一张图只讲一件事
- 当前步：红框 + 红标签，全图只有它一个红色元素。
- 已完成步：降级成灰色 `✓` 小标签（`done:true`），不画框，不抢注意力。
- 未到达的步：**不出现**。不要提前画出来。

## 2. 复刻，不是截屏
默认路线是「HTML 复刻界面 → 截图」，不是截屏打标。理由：
- 干净：没有书签栏、没有别人的头像、没有系统通知。
- 可控：想让哪个按钮出现就出现，想让它变灰就变灰。
- 可重渲：改一句文案不用重新截一遍。
- 可标注：元素有 id，标注按元素算位置，不靠手数像素。

**例外**：界面极复杂（设计工具、IDE、地图、有真实数据的后台）→ 走「截图打标」路线：
把真实截图当底图（`<img>` 固定尺寸），标注引擎照用，`target` 指向叠在图上的空 div。

## 3. 尺寸与字号
- 画布固定 `1500×720`（横版）/ `750×1334`（手机竖版），`--scale 2` 出 2x。
- 界面正文 ≥ 12px，标注标签 14px，标题 25px。低于 12px 在手机上看不清。
- 长图宽度用 2x（3000），1x 放大看会糊。

## 4. 标签文案
- ≤ 18 个字，动词开头：「先把这个开关打开」而不是「开发者模式开关说明」。
- 标签里不解释概念，只指动作。概念放标题下的 `sub` 或页脚。
- 术语首次出现给白话（「清单文件」＝ `manifest.json`）。

## 5. 指向
- `side` 优先 `right`，其次 `below`；`left` 只在前两者会遮住其他可点元素时用。
- 标签不许压住任何**下一步要点的东西**。
- 一个元素只挂一个标签。

## 6. 真正的卡点要讲死
每张教程都有且只有一个「用户会在这里失败」的地方（选错层级、选错账号、找不到入口）。
这个点必须用**具体判据**说，不能写「选对文件夹」：
> 能直接看到 `manifest.json` 才算对 ← 可验证
> 选对文件夹 ← 不可验证

## 7. 报错写进图里
把最常见的报错原文 + 一句话解法放在画面里的 `.trouble` 条上，别放在正文外。
用户是在图里找答案的，不会去读说明文档。

## 8. 细节必须真
扩展名 / 版本号 / ID / 图标 / 菜单项文字，全部用真的。
一处 placeholder 会让人怀疑整张图是不是编的。
（扩展 ID 算法：`sha256(绝对路径)[:32]`，每位 hex 映射 `0-f → a-p`。）

## 9. 状态要自洽
开关画成开着的，就别在文案里说「打开它」；按钮还没出现的步骤，就别把按钮画出来。
Chrome 在开发者模式关闭时**不显示**那一排按钮 —— 这类真实行为必须遵守。

## 10. 步数上限
一次最多 4 步。超过就拆成两张图（「安装」「首次使用」），别把长图做成 8 屏。
